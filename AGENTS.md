# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

AI Deck uses the selected light Parallel Desk design with side-by-side Codex and Claude activity. The prototype demonstrates shared knowledge from both providers, shared skills and settings, and workspace plugin management with simulated agents.

The interactive sandbox should feel like a coding session. Keep user turns and the two agent activity feeds, show file reads and reviewable edits, and derive sandbox check results from the edited workspace.

The Electron desktop app uses the Codex-style navigation rail with project/task search, a shared Timeline or Split view, and the Changes, Usage and Context inspector. Scheduled runs stay in a separate view with their own history and fresh worktrees. Feature map distinguishes the connected desktop actions from features opened in the provider's app.

Keep the desktop interface compact. Use a smaller default window and tight spacing across navigation, chat, forms, and the inspector while keeping labels readable and controls easy to click.
Keep the compact defaults at 100% and save UI scale and text size separately in the desktop profile. Animate the first paint and menu entry briefly without delaying navigation. Show a loading indicator only while the corresponding data is pending and respect reduced motion.
Keep model and effort controls for both agents visible in the desktop composer. They must be usable before a repository is opened and apply through each provider's runner.
Show account quota used beside each provider and in the lower navigation rail. Use the highest current reported quota window, and show a dash when a percentage is unavailable. Usage keeps provider quota resets and credits separate from clearing an AI Deck hold and from per-session cost estimates. Using an earned reset requires an explicit user action.
Keep Settings organized by category and use the full work area for main menu pages. Let users resize Projects and Inspector with a mouse or keyboard and save their widths locally. Keep the chat and composer clear of panels. Dock whichever panels fit, open a requested panel in its own view at compact widths, and keep the current draft and activity when returning to chat. The composer keeps both model and effort controls visible and groups attachments, context and run scope together.
Settings uses a searchable Personal, Integrations, and Coding index. Label controls hosted by the original provider. Import previews compatible provider model preferences before applying selected values to AI Deck defaults. Keep credentials and account controls in the provider. Edit native hooks in their original local settings, keep trust explicit, and preview the script, folder, and test input before executing it.
Foreground sends let Codex enforce its native hook trust. Claude receives command hooks from user settings and explicitly reviewed project definitions, while AI Deck controls tool approvals. Record hook outcomes from the provider separately from model replies.
Show each agent’s role, workflow order and review input before a team run. Separate resuming the original session, forking into a worktree and handing off selected excerpts in Recents. A saved or queued team brief must reach the runner, and sequential handoffs should be visible in the timeline. Shared skills are explicit context, while composer slash commands dispatch only supported AI Deck actions.

Default new tasks to builder then reviewer. Keep parallel modes available and label their handoff timing. Separate edits may pass a bounded report from the teammate's previous round. A standalone greeting in an ordinary team mode uses only the lead and keeps native Recents clear of transient turns. Reject repeat submissions of the same autosaved draft.
Route clear standalone requests for the two agents to talk to a short, tool-free discussion. Relay the first reply through AI Deck. Keep discussion and greetings out of implementation and review context. Group work activity into collapsed timeline blocks with short command labels and expandable details.
Distinguish review evidence and command outcomes from model completion. Worktree base updates create a verified copy and preserve the source task and its staging.

Team planning starts a read-only planner and saves its decision. Implementation always requires a separate user approval, including for scheduled plans. Earlier ready plans remain accessible within the retained task history.
Queued messages keep their team brief and pause for review when the effective model settings, shared context, or project permissions change. Combining selected files from parallel worktrees creates a separate task only after verifying both source snapshots.

Team inbox lists plans, reviews, usage handoffs and paused queues across projects. Keep unresolved ready plans beyond recent run retention until implemented or dismissed.
The local skill library saves explicit snapshots. A project keeps its installed version and enabled preference until the user previews and updates that copy.

Enter sends or queues by default, and Shift+Enter starts a new line. During an eligible run, Ctrl+Enter and the Steer button let the user target an available agent while preserving the run's mode, setup and worktree. Claude follow-ups stay in that CLI session and run after its current response. Saved plan approval compares current Git and effective writer settings to the planning snapshot. Writer completion and observed Git changes remain separate from the user's implementation decision.
When a schedule is held before starting for usage, retain one occurrence across app restarts. Resume the same occurrence on an enabled schedule without replaying additional missed slots.

The Inspector defaults to a compact task Outputs tab with previews, observed running processes, and sources. Keep the panel task-scoped and collapsible.

Recents pulls local Codex and Claude Code session lists on request and keeps local pins across restarts. Load older messages or search inside a preview. A native handoff creates a new AI Deck draft from explicitly selected quotes. Suggest the source repository even if it has not been opened in AI Deck. Show the checked destination repository, branch and commit, then verify them again on first send before preparing the detached worktree.
Recents supports multiple selection and selection of visible rows. Confirm permanent deletion with the exact list grouped by source. Keep failed deletions selected with their reasons and reuse each provider’s transcript checks.

Linked sessions keep a native conversation ID per provider. Verify the exact checkout and the latest saved provider history before sending. In the original folder, resume the original ID. An isolated worktree copies supported working changes and forks the source conversation on its first native turn. Keep the switch context visible and optional before a linked turn starts. Combine native messages with AI Deck run evidence in the linked timeline. Save the user's next step per task, and preview any selected Git diffs and recorded command results before forwarding them. Keep receipts tied to the receiving turn and its outcome. Offer a reviewed handoff when a linked provider is limited, keep checklist steps with their evidence turns, and explain blocked sends near the composer. Applying a linked copy verifies both checkouts and the original staging, then uses the reviewed Git patch without staging or committing it.

Autosave the composer per task with a small local checkpoint. Keep recorded command outcomes in an active-run checkpoint and merge it on restart. Linked watch polling yields to foreground actions and pauses when the app is hidden. After a restart, show interrupted turns, observed command outcomes and current Git changes before drafting a continuation. Undo Apply uses only the recorded patch and checks the original branch, working files and staging before confirmation. Ready to ship reports staging, open steps and the freshness of observed test results, and offers editable commit and PR drafts for copying.

The Team Plan board keeps responsibility text with the role when swapping Codex and Claude. Save role defaults per task. The active run and already queued messages retain their own assignments.

A Team Plan one-message override is consumed when the user sends or queues the draft. History and queued role details show recorded assignments. Usage handoff moves the original writer's responsibilities to the replacement. Role presets save workflow and written role text locally.

Auto Team exchanges a read-only proposal and assignment before the user approves implementation. Split work starts from two verified clean worktrees. Show each agent’s current stage and animate only active work. Keep a bounded review/fix/recheck loop, record observed tests separately, and verify saved Git snapshots before resuming a usage-limited stage or offering combined files.
Auto Team plans show each writer's paths and acceptance criteria. Forward changed paths and recorded checks with each handoff. Run project-required checks on a copy of the final checkout and keep the repair round within the approved assignments. Include local hook definitions and trust settings when comparing setup before approval or a queued turn.
Session Team saves ordered members, roles, models and instructions to one task. Keep each member's run record distinct even when several use the same provider. Send teammate reports in order, show which members can edit, and use separate settings to attach shared context or a tracked diff to Gemini or Ollama.
Session Team excludes recent rounds and any report derived from project data when sending to Gemini or Ollama unless the session opts in. Show the effective sharing scope before a send. Tracked patches for those providers omit sensitive paths, binary contents and the full repository path list.
The Session Team editor shows the ordered roster and one selected member, supports dragging and keyboard reordering, and keeps Save accessible as the list grows. Separate data sharing and connections from member fields. Usage separates run reports from account limits and opens the latter from provider quota badges.
Branching Session Teams save one lead and one upstream member per remaining member. Show the saved graph in the editor and the recorded graph in a run. Forward only the direct upstream report through the existing sharing controls. Skip unavailable branches and their descendants, and require a ready lead. An optional wrap-up is read-only and receives only authorized reports. Parallel text branches may overlap Gemini and Ollama at the same dependency level when enabled and Low RAM is off. Keep native turns and worktree writes serial.
Team map arrows follow the saved handoff direction. Allow connections by dragging or clicking ports, and let users select an existing arrow to change its upstream sender. Keep keyboard and dropdown controls available and reject links that would create a loop.
Builder-reviewer runs use the saved Team Brief and bounded handoff packets with observed check freshness. Show the combined answer directly in Timeline and Split, with commands and individual reports folded. When a foreground team's turn budget allows, its lead writes the final answer from completed reports in a tool-free turn. Show a bounded answer from saved reports when the lead turn is unavailable. Economy and Normal use at most one review. Thorough allows one scoped repair and one recheck against verified Git evidence. Keep app turn counts separate from provider-reported tokens and account usage.
The default desktop chat uses right-aligned user bubbles, a compact elapsed-time disclosure per turn, and plain left-aligned replies. Keep permission requests and actionable warnings in the conversation. Keep original provider attribution in linked chats and open detailed work only on request.
The composer lets users preview and choose builder and reviewer context separately and set a turn limit for the run. Economy and Smart start fresh by default. Send saved Team Decisions only within their Git scope. Smart skips model review only for a verified small text-only change. Resume a held review against the recorded checkout and evidence without rerunning the builder.
Separate edits requires distinct responsibilities. Keep the builder-reviewer workflow after a review-only continuation. When the user requests a peer review without a diff, distinguish review of the report from review of a code change.
Separate edits requires disjoint repository paths in Team Brief. Verify both worktrees before provider calls and compare their Git changes with the assigned scopes afterward. Hold the queue if scope verification fails. Combining worktrees requires choosing only one version of a conflicting path.
Keep Separate edits provider chats separate from ordinary builder chats. A different base or assignment starts fresh provider history for that lane.
When Separate edits runs one writer at a time, send the first writer's verified file list to the next writer without a separate model turn.
