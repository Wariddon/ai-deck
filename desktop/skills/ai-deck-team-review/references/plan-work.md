# Plan shared work

## Planner

Describe a testable deliverable for each role, its exact file scope, the interface or evidence it consumes, and what it must hand over. Group edits that share a data contract; use separate writers only when their scopes can remain independent. Tie acceptance checks to observable behavior. Identify a dependency before assigning work that needs it. Use AI Deck's existing plan format, roles and approval flow; do not create another team, commit work or request new setup.

Include `inputs`, `outputs` and `readyWhen` in the supplied structured plan format. Name concrete interface signatures, artifacts or evidence; conditions describe what must be verified before downstream work relies on an output. In a free-text Session Team plan, use the same three sections in its existing report. Independent writers must consume inputs available at the shared base; keep dependencies on merged work for integration.

## Builder

Implement your assigned deliverable and preserve the teammate's file scope. If a shared interface needs to change, explain its effect on the next role before expanding the work. Hand over the changed paths, the relevant interface or behavior, observed checks and any remaining criterion. Reuse the existing plan and evidence instead of making the teammate rediscover the task.

Use the plan's inputs, outputs and handoff conditions. If no structured plan was needed, identify these briefly in the existing handoff report. Verify required inputs before dependent edits, continue independent work where possible, and state unmet conditions. Distinguish delivered outputs and observed checks from expected results. A completed response alone does not make a handoff ready; incomplete work can still go to a reviewer for inspection.
