# Observed member checks and automatic guides

AI Deck adds a short member-specific verification guide to existing native project-team turns. It works with builder/reviewer runs, the native stages using that shared guidance, and Session Team. No setup button, external team daemon, extra model request or provider conversation is created. The saved roster, Model/Effort/Speed, permissions and turn limit remain the user's choices.

Guides have role-specific planning, implementation, review or summary instructions. When repeated observations exist, they add the number of matching checks that passed out of the observed sample. A previous failure emphasizes reproducing the relevant failing behavior and verifying the current checkout. The text comes from fixed local templates and numeric counters; provider replies, commands, file paths, personal data and generated coaching prose are not copied into this memory.

Counters distinguish tests, build checks and other explicitly observed acceptance checks. One run supplies at most one sample per member/skill, regardless of the number of commands or repairs; any observed failing check in that sample keeps it failed. These are check-outcome rates, not a general intelligence rating, a causal finding about who introduced a bug, or proof that the next result is correct. Fewer than three samples remains insufficient for rating in the prompt. Plans and reviewer PASS claims alone never earn scores.

Eligibility requires a native command-start/result pair attributed to the active member guide, an actual provider dispatch, completed member status, a supported command completion and a matching checkout observation from the existing handoff/final-evidence barrier. No additional Git/test commands are launched for learning. Changed or unknown evidence, old unbound runs, hooks, background/compound shell commands, transport failures, quota-limited or interrupted members and timeout/interrupt exit codes do not contribute. Checks executed by AI Deck itself are not credited to a model. Missing evidence is unknown rather than a zero score.

Rows live in the existing local workspace profile, scoped by canonical project, native provider, role, selected model and all saved model settings plus CLI version. A catalog-resolved model identity is included where available; a reported reroute to a different model stays unrated. Session Team rows also bind the task/member identity. Unspecified model choices stay unrated instead of guessing the provider default. Changing a model, effort, speed, provider, role or project cannot reuse an unrelated score. Supplemental providers never receive or populate native member counters. Disabling shared team guidance or native handoff history sharing also withholds this added guide and its learning for that turn.

Each waiting job and queued message captures its guide snapshot. Results from the preceding turn may update the workspace counters without changing those already queued instructions. Only actual provider dispatch records an applied-guide receipt in the saved run; outcomes are committed through the existing workspace save, with rollback on write failure. Storage retains at most 128 profiles and 128 deduplication IDs per profile. It contains hashes, small identifiers and counts, not an archive of task content. It is not fine-tuning or a background training process.

Equivalent saved setting fields use a stable order when identifying a member. Actual different model/effort/speed values remain separate. The existing check-snapshot budget (six checks, or twenty-four when explicit references exist) is independent of the compact command-history ring. Learning keeps those already captured references until the final evidence barrier; later activity cannot evict a matched failure. Changed checkouts still invalidate the retained evidence, and no extra checkout reads are added. A test filename containing words such as `build` does not change its outcome category.

The feature is an independent implementation inspired by the per-seat scores and coaching concepts in [Power AI Ranger](https://github.com/panusbodee-owen/Power-Ai-Ranger-Skill/tree/2a0e70c15d238f1cc64447351492d9b68bb8e82e). No upstream Python runner, dashboard, database, prompts or code were vendored. Its separate CLI/session lifecycle and external-provider policies do not replace AI Deck's native sessions and resource/permission guards. Automatic model selection, new API gateways, budget reservation and race/voting modes are outside this change.

See [validation](validation.md) for controlled provider scenarios, real local check execution, queue isolation and the installed-release proof. Actual Claude inference remains skipped as requested.
