# Memory, context and code tools

AI Deck supplies project context and read tools through ordinary chat. It keeps the existing note/skill selections and each member's data-sharing permissions. These changes add no primary controls or model turns.

Saved notes are snapshots. New imports retain their project, content SHA-256, capture time and source commit when imported from Git. A bounded origin check labels matching bytes, changed sources or unavailable sources at prompt preparation. The prompt still includes only the saved text the user selected; it does not copy replacement content automatically. Older notes remain readable as snapshots with an unknown original revision. An explicit library copy belongs to its destination project. A snapshot belonging to another project is withheld with its private title and path. Conversation-only keys do not depend on the folder from which the app starts.

Team Decisions match the canonical repository, branch and commit. Identical branches/commits in another repository cannot inherit a decision. Older decisions without repository identity remain in the existing editor and need its existing refresh action before automatic reuse. This does not prevent ordinary chat. Native Claude memory opt-outs and its user-selected store remain native preferences; AI Deck does not mirror private account/web memory between providers.

Tool observations carry their source, checkout key, time and result hash. Quoted teammate observations explicitly state that freshness has not been rechecked; they are not current verification results. When the user excludes the diff from a standard native review, AI Deck does not supply its built-in repository tool lease to that reviewer. Writer tools and explicitly configured independent integrations retain their existing scopes. Supplemental Gemini/Ollama report/context opt-outs remain separate and continue to filter project-derived reports.

Serena starts lazily on a code request and is shared by members using the same checkout during that run. Its home and project metadata include a canonical checkout key, preventing collisions between projects with identical folder names. Managed runtime setup repairs a missing `uv/uvx` using an isolated Python environment, following the supported [uv installation method](https://docs.astral.sh/uv/getting-started/installation/#pypi). Only the child PATH is changed. Existing user/global runtimes and shell profiles are not rewritten. Semantic MCP requests have a twenty-second deadline, and Stop revokes their owned processes.

If semantic lookup is unavailable, a JS/TS identifier can use the local source graph. Other supported text sources, including Python and PHP, can use bounded literal search. A literal match is neither a semantic definition nor a reference result; qualified names may need a simpler query. Language-server availability still depends on that language's installed runtime. Python find/reference/update paths were exercised against the existing local Serena and its pinned Pyright dependency; this does not certify every language server.

The graph shares a bounded worker but correlates every request and response by ID and checkout. Cancelling one request does not consume a peer's result. Idle cleanup waits until no requests remain; closing the worker settles outstanding requests. The source scan attempts at most 1,600 files, with 256 KiB per file and twelve MiB total bytes, including skipped binary/invalid files. It rehashes current sources before cache reuse and labels partial coverage. A global worker cache is an implementation optimization, not shared conversation memory.
