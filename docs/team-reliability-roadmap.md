# Team reliability roadmap

This preserves the ten-phase scope agreed in chat. Validation records distinguish controlled provider fixtures, actual native CLI calls, source builds and installed releases. Phases can share fixes; a bounded scenario does not complete every item in a later phase.

1. **Interrupted work and duplicate-send recovery.** Check abrupt termination, uncertain transport, original history, partial replies, drafts, files and persistent builder IDs. Implemented in 0.9.165 with 22 controlled crash boundaries and bounded native-provider checks; operating-system network/power outages remain outside that proof.
2. **Chat switching correctness.** Exercise Recents, Ask, Team and Fork while other replies arrive. Keep Model, Effort, Speed, Permission, text, images, Stop and approvals scoped to their chat. Include late settings/rename/archive replies, project switches, frozen queued choices and restart. Implemented and exercised in the controlled 0.9.167 matrix; see validation for release checks and limits.
3. **Startup and interaction speed.** 0.9.168 is installed with hard metadata deadlines, concurrent normal-mode startup quotas and deferred long-history formatting. All 397 tests and the packaged startup, 2,400-message interaction and 1,200-file Recents checks pass. RAM/CPU/I/O observations cover separate 100-minute and 74-minute workloads; Windows shutdown interrupted the first and the agent ended the optional second run after the user raised the excessive wait. Neither establishes an uninterrupted two-hour pass. No endurance process remains running. Windows process counters include pipes, devices and fixture writes; whole-host disk snapshots are recorded separately. See validation for evidence and limits.
4. **Concurrency and resource cleanup.** Implemented in 0.9.169 with short targeted checks: two active jobs, a third waiting, eligible FIFO order without folder head-of-line blocking, RAM/folder/native-session guards, targeted Stop, pool shutdown fences and owned process-tree cleanup after success, failure, cancellation and native-root exit. Low RAM changes remain an idle action so running/queued setup snapshots stay frozen; internal limit-transition checks preserve active peers. The production desktop matrix and real Node protocol/process fixtures are separate from live-provider inference. See validation for exact scope.
5. **Multiple writers and changing plans.** Installed 0.9.170 routes a scoped correction to the unique recorded upstream file owner, holds dependent work for unresolved plans or stale reviews, checks frozen setup before each handoff and keeps independent branches usable. Short controlled desktop scenarios cover both native role orders, earlier/ancestor owners, unavailable branches, changed native-hook requirements and findings beyond long display previews. The global one-repair budget and serial native writes remain; ambiguous/mixed ownership requires another plan. See validation for package and installation evidence and provider limits.
6. **Observable acceptance.** 0.9.171 binds bounded file/image/JSON artifacts to exact native or required-check completion and the current checkout, including named build/API/UI checks. Handoffs rehash ignored artifacts, share reads across contracts and distinguish recorded, verified, incomplete, stale and failed evidence. Explicit unresolved references hold final integration and automatic follow-ups; existing history shows Session Team evidence. Controlled scenarios use real loopback HTTP, build scripts and production-renderer captures in both native role orders. Target/environment assertions and verifier coverage remain specific to the task; a screenshot hash is not visual certification. See validation for exercised paths and installation status.
7. **Integration and Git conflicts.** 0.9.172 binds integration previews and replay to source staging, branch, HEAD and physical repository identity, verifies managed ownership before updating bases and rejects source changes before publishing a copy. Bounded real-Git coverage includes same-line, rename/edit, rename/delete, binary and file/directory conflicts, partial staging, new/ignored files, successful base replay and scoped undo. Undo holds relocated or position-shifting applied blocks rather than reversing a different matching copy. Production app scenarios cover combined checks, invalidated candidates, rename/deletion selection, stale staging previews and failed-candidate cleanup. Original worktrees remain intact; see validation for exercised scope and release status.
8. **Memory, context and code tools.** 0.9.173 isolates concurrent worker replies and cancellations, canonical-checkout Serena profiles and project-scoped decisions. Saved context has bounded source attribution/freshness labels without silently importing replacement text. Native/supplemental sharing opt-outs retain their scope, including report-only repository-tool exclusion. Real local Serena checks cover same-named Python projects, references and source refresh; controlled tools exercise JS/TS graph and Python/PHP literal fallbacks, rejected-source I/O limits and multiple requests. See validation for package/install evidence and the distinction between real tools and simulated provider inference.
9. **Screen, browser, voice and Cloud.** Installed 0.9.174 fixes browser intent false positives, tab creation approval, pending window-action cancellation, stale control observations, voice process ownership and cross-chat cancellation, and bounded Cloud reads/list parsing. Controlled production IPC scenarios cover task/project switches, minimize and explicit voice cancellation without model calls. Actual local checks cover Codex Cloud listing and Windows speech synthesis; browser connection and microphone transcription are not certified by those checks. Unsupported native Windows CLI desktop dragging/multiple windows, Cloud writes and realtime voice remain bounded by provider support and action permissions. See validation and the capability matrix for evidence and unavailable interfaces.
10. **Product and release verification.** Installed 0.9.175 verifies thirteen Settings categories, compact layouts/search, draft/image preservation and settings rollback on write failures. General Quit keeps unsaved drafts open after a failed write. Current starter instructions, path-override exclusion and a source/version/file-hash manifest bind the portable payload; the actual extracted ZIP passes verification. Controlled original-chat attachment and update-bell regressions pass, and the isolated profile survives previous/new program-version reopening without replay. Actual Windows checks visit all thirteen categories and the reopened installed chat; protected user data remains unchanged. See validation for the 446-test baseline, package/installation evidence and remaining native-provider/voice limits; local completion is not publication.
